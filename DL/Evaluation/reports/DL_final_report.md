# CargoMind Stage 02 — Deep Learning Forecasting: Final Report

**Status: COMPLETE WITH LIMITATIONS.**

This is a **research / prototype forecasting pipeline trained and evaluated on synthetic data.** It is **not** a validated production forecaster for real ports, and nothing here establishes performance on real port data.

The research phase is frozen: no further data generation, retraining, tuning or test-set use. This report consolidates the stage. The detailed source reports are listed in section 16.

---

## 1. Problem statement and forecasting objective

Forecast **container dwell time at each port for the next hour**:
- **Input:** the previous 12 consecutive hourly observations of that port.
- **Output:** a single regression value in hours.
- **Purpose:** to provide CargoMind with an early signal of rising port congestion.

This is separate from the ML stage's shipment delay-risk classifier. No mapping from dwell forecasts to risk classes is defined, and none is implied.

## 2. Dataset and the synthetic-data limitation

| Item | Value |
|---|---|
| Source | `ML/Dataset/Processed/`: `port_hourly_telemetry`, `weather_hourly`, `disruption_events`. Synthetic, generated by `ML/Dataset/Raw/generate_dataset.py`. |
| Coverage | 10 ports × 1,000 hours (2025-01-01 00:00 → 2025-02-11 15:00 UTC), 41.7 days |
| Structure of the target | A slowly varying per-port level, plus multi-day backlog episodes driven by capacity cuts, plus independent hourly noise of about 3.5–4.4 h SD (pooled ≈ 3.9 h) |
| Provenance | 4.6 % of dwell values were reconstructed during cleaning by an undocumented method. They are flagged per cell (`DL/Dataset/data_audit/lineage/`). |

**Limitation:** the data-generating process is simple and fully synthetic. Relationships the models learn are properties of the simulator. Real-world transfer is untested.

## 3. Features and sequence construction

Built by `DL/Dataset/scripts/build_dl_dataset.py` and documented in `DL/Dataset/reports/DL_dataset_construction_report.md`:

| # | Channel | Raw unit | Train-fitted transform |
|---|---|---|---|
| 0 | dwell (history) | h | Per-port z-score |
| 1 | utilization | % | ÷ 100 |
| 2 | labour_strike | 0/1 | — |
| 3 | wind_gust | km/h | Global z-score |
| 4 | disruption_active | 0/1 | — |
| 5 | disruption_hours_elapsed | h | log1p + global z-score |
| 6 | vessels_at_anchor | count | log1p + per-port z-score |
| 7 | dwell_reconstructed | 0/1 | Appended by the loader from provenance |

- **Windows:** inputs are hours t−11 … t; the target is dwell at t+1.
- **Exclusions:** reconstructed targets are excluded. Reconstructed inputs are kept and flagged.
- **Scalers:** fitted on training hours only, with reconstructed cells excluded.

## 4. Split methodology

- **Cut-offs:** global hour cut-offs, the same for every port: train 0–699, validation 700–849, test 850–999.
- **Embargo:** a window is kept only if all of its input hours fall in its target's split, so no hour is shared across splits.
- **Kept windows:** 6,579 / 1,306 / 1,318.

**Test-set status:**
- The test split was used **once** for the original selection (B_w).
- The independent audit then scored all 13 then-existing experiments on it **as diagnostics**.
- It is therefore **not an untouched final holdout.** The Transformers were not evaluated on it.

## 5. Architectures evaluated

| Name | Architecture | Training protocol | Params |
|---|---|---|---|
| Basic LSTM (A) | 1-layer LSTM, 32 units, final hidden state → linear | Plain MSE on the scaled target | 5,409 |
| A_w | Same | Hour-weighted MSE | 5,409 |
| B_w (original selection) | LSTM + 4-d port embedding | Hour-weighted MSE | 5,453 |
| **C_w** | LSTM predicting a correction to the window's EWMA (α = 0.2) | Hour-weighted MSE | 5,409 |
| **GRU** | 1-layer GRU, 37 units + port embedding | Hour-weighted MSE | 5,299 |
| **Transformer T** | Linear(8→32) + sinusoidal PE + 1 encoder layer (4 heads, ff 64) → last step → linear | Plain MSE | 8,865 |
| **Transformer T_w** | Same | Hour-weighted MSE | 8,865 |
| Ablations | B_w minus one feature group (7 variants) | Hour-weighted MSE | 4,557–5,453 |

"Hour-weighted MSE" weights each sample by its port's dwell variance, so the loss equals MSE in hours, which is the selection metric. Plain MSE on per-port z-scores under-weights high-variance ports (NLRTM) and was the cause of the basic LSTM's failure.

## 6. Training methodology

- **Optimiser:** Adam, lr 1e-3, batch 64.
- **Regularisation and schedule:** gradient clipping 1.0; ReduceLROnPlateau (factor 0.5, patience 5).
- **Early stopping:** patience 15 on **validation RMSE in hours**; the best checkpoint is restored.
- **Seeds:** 0–4 for every configuration.
- **Determinism:** deterministic CPU kernels and seeded shuffling of training windows only. Retraining reproduces checkpoints exactly.

## 8. Baseline comparison

- **The task is close to its noise floor.** With hourly noise of about 3.9 h, EWMA's 4.30 h leaves at most about 0.4 h for any model to gain. The best neural models capture about a third of that headroom on validation.
- **Persistence** (5.66 h) copies the hourly noise and is not a meaningful benchmark. The 12-hour mean (4.33 h) is close to EWMA.

**On the old test split (diagnostic only, from the independent audit; not a holdout):**

| Model | Test RMSE |
|---|---|
| EWMA | 4.234 |
| B_w | 4.143 ± 0.058 |
| GRU | 4.101 ± 0.018 |
| C_w | 4.067 ± 0.010 |

- The validation ranking held there.
- The Transformers were deliberately **not** scored on test.

## 9. Error and subgroup analysis (validation)

n = windows (ports). RMSE in hours, 5-seed means.

| Subgroup | n (ports) | EWMA | GRU | C_w | T_w |
|---|---|---|---|---|---|
| Normal (no disruption) | 1,204 (10) | 4.289 | 4.210 | 4.218 | 4.184 |
| Disruption active | 102 (5) | 4.383 | 4.116 | 4.143 | **3.892** |
| Disruption onset, 1–6 h | 36 (4) | **3.898** | 4.232 | 4.399 | 3.938 |
| Disruption 7–24 h | 44 (4) | 4.961 | 4.322 | 4.207 | **3.972** |
| Disruption > 24 h | 16 (3) | 4.025 | **3.580** | 3.669 | 3.852 |
| Labour strike | 9 (1) | 4.708 | 4.222 | 4.373 | 4.493 |
| Extreme, known at t (top-decile window level) | 137 (10) | 4.447 | 4.269 | **4.189** | 4.237 |
| Extreme, realised (top-decile actual dwell) | 137 (10) | 6.653 | 6.687 | 6.732 | 6.704 |

### Model weaknesses (failures)

- **Disruption onset.** In the first 6 hours of a disruption, the GRU and C_w are worse than EWMA (+0.33 and +0.50 h). T_w is about level with EWMA, so no model improves on it there.
- **Port-specific behaviour.**
  - T_w is worse than EWMA at CNSHA (+0.08 h); every other port improves.
  - Plain-MSE models fail at NLRTM and USLAX (the loss/metric mismatch).
  - On the old test split, the original B_w saturated near 80 h during an unprecedented MYPKG strike while dwell rose past 90 h. This **out-of-range extrapolation failure** is the most important known failure mode. C_w's EWMA skip connection does not show it there; the Transformers were not tested on that episode.
- **Systematic bias.** The hour-weighted models under-forecast slightly overall (−0.09 to −0.23 h). The original B_w reached −0.59 h on the old test split.

### Statistical limitations (not model failures)

- **"Under-prediction at extremes" measured on realised top-decile dwell is largely regression to the mean.** Every forecaster, including EWMA, has a bias of about −6 h there, because those hours were selected for large positive noise. Measured on states known in advance (top-decile window level), all neural models beat EWMA.
- **Thin subgroups.** Strike windows (9, one port) and long disruptions (16 windows, 3 ports) are too small to rank models. Onset results flipped sign between the validation and old test splits for the original model.
- **Short validation period:** 150 hours, with 5 ports having any disruption. Per-port differences under about 0.1 h are within episode-to-episode variation.

## 10. Independent evaluation findings

From `DL/Evaluation/evaluation_engineer/`, verdict **FAIL – NOT READY** for the original B_w selection.

**Verified:**
- No leakage.
- Training-only scalers.
- One-time test use.
- Exact reproducibility.
- The original selection rule picked a dominated configuration (B_w over C_w and the GRU).
- B_w's gain over EWMA was within the tie band on validation.
- B_w failed in extreme and novel conditions and under-forecast.
- The inference layer accepted invalid input silently.

**How each finding was addressed:**

| Audit finding | Resolution |
|---|---|
| M1: dominated selection | The original selection was not used. The candidates are now recorded with their validation ranking, and **no decisive winner** is claimed (section 11). |
| M2: weak gain over EWMA | Unchanged in substance. The best models gain 0.08–0.13 h on validation. EWMA remains the operational fallback. |
| M3 / M4: extremes, bias | Separated into a measurement artefact and genuine failure (section 9). The genuine out-of-range failure remains a documented limitation. |
| M5: inference not ready | **Resolved:** `DL/DL/inference/` (section 12), with 27 tests. |
| M6: overstated disruption claim | Superseded by the subgroup table in section 9, which reports n and port counts and states that onset is weak. |
| Minor m1–m6 | m1/m2 (metadata text, test log) recorded, not changed (research frozen); m3 dependence-aware statistics are in the audit; m4/m6 addressed here; m5 (CSVs git-ignored) remains a repository decision. |

## 11. Model-selection decision and justification

| Role | Model | Justification |
|---|---|---|
| **Operational forecast and fallback** | **EWMA (α = 0.2)** | Simple and transparent, with no extrapolation failure mode. No neural model has been confirmed on independent held-out data. |
| **Leading research candidate** (inference default) | **Transformer T_w** (`transformer_t_w`, seed 1) | Lowest validation RMSE, MAE and \|bias\|; best on disruption-active windows (every seed); about level with EWMA at onset |
| Competitive alternatives | **GRU** (`gru`, seed 0) and **C_w LSTM** (`c_w_lstm`, seed 2) | Within 0.05 h of T_w overall. C_w is best on known-at-t extremes and structurally cannot fall below EWMA when extrapolating. GRU is best on long disruptions (16 windows). |
| Not recommended | Basic LSTM, Transformer T, original B_w | Worse on validation, or superseded |

**No statistically or practically decisive winner exists among T_w, GRU and C_w.** Confirming any of them requires new held-out data (for example, a later synthetic period or real port telemetry) and a selection policy fixed before it is scored. The registry seed of each model is its best-validation seed, which is optimistic for a single checkpoint; the 5-seed means above are the honest estimate.

## 12. Inference architecture and usage

```
DL/DL/inference/
  validation.py      raw-window checks (InputValidationError); dwell-history checks for EWMA
  predictor.py       DwellForecaster, load_model(), forecast(), DwellPrediction, ModelLoadError
  fallback.py        ewma_forecast()  (reuses cargomind_dl.baselines.ewma_window)
  registry.py        candidate definitions + registry loading / SHA-256
  build_registry.py  regenerates model_registry.json from existing result tables (no training)
  model_registry.json
  demo.py            sample prediction
```

**Pipeline:**
1. Validate the raw window.
2. Apply `cargomind_dl.sequences.transform` with the saved `scalers.json` (the dataset build's own code; nothing re-implemented).
3. Select the checkpoint's channels **by name in the checkpoint's order**.
4. Run the model in eval mode under `torch.no_grad()`, with the port index for embedding models.
5. Invert with `cargomind_dl.dataset.to_hours`.

Inference imports no training code.

**Loading** (`load_model(name)` / `DwellForecaster(checkpoint)`):
- LSTM, GRU and Transformer checkpoints, including old checkpoints without `model_type` and reduced-channel ablation checkpoints.
- The checkpoint SHA-256 must match the registry.
- `feature_schema.json` and `scalers.json` must be present **and** match the hashes stored in the checkpoint.
- The schema channel order must match the preprocessing code.
- An unknown model, or missing or altered artifacts, raise `ModelLoadError`. **No other model is ever substituted.**

**Input:** a `pandas.DataFrame` of 12 rows, oldest first, with raw-unit columns:
- `ts_hour` (UTC);
- `dwell` (h);
- `utilization` (%);
- `labour_strike`, `disruption_active`, `dwell_reconstructed` (0/1);
- `wind_gust` (km/h);
- `disruption_hours_elapsed` (h);
- `vessels_at_anchor` (count).

**Rejected** with `InputValidationError`, never repaired:
- not a DataFrame (positional arrays are refused because feature order can't be verified);
- missing columns;
- ≠ 12 rows;
- reversed, gapped or off-the-hour timestamps;
- NaN or ±inf;
- non-numeric columns;
- non-binary flags;
- out-of-range values;
- non-integer anchor counts;
- elapsed hours > 0 with no active disruption;
- **already-standardised input** (dwell maximum < 10 h, or negative dwell);
- utilization supplied as a fraction;
- an unknown or wrongly-cased `port_id`.

**Output** (`DwellPrediction.to_dict()`):
- `predicted_dwell_hours`;
- `method` (`neural` | `ewma_fallback` | `ewma_baseline`);
- `model_name`;
- `model_version` (checkpoint path @ SHA-256 prefix);
- `port_id`;
- `window_end_utc`, `target_hour_utc`;
- `warnings`, which flag reconstructed inputs and a latest dwell more than 4 training SDs from the port mean (outside the training range);
- `note`: point forecast only.

No confidence intervals or probabilities are produced.

**Fallback:**
- `fallback="none"` (default): every error is raised.
- `fallback="ewma"`: if the neural model can't be loaded or the window fails validation, the EWMA forecast is returned with `method="ewma_fallback"` and the reason in `warnings`. This only happens when 12 valid, ordered, raw dwell hours are present; otherwise the error is raised.
- `model="ewma"` returns the EWMA baseline directly, labelled `ewma_baseline`.

**Example:**

```python
from dl.inference import forecast, InputValidationError, ModelLoadError
res = forecast(window_df, port_id="SGSIN")                                  # transformer_t_w
res = forecast(window_df, port_id="SGSIN", model="gru", fallback="ewma")   # explicit model + explicit fallback
print(res.to_dict())
```

## 13. Known limitations

1. **Synthetic data only.** This is a prototype research pipeline; no real-port validity is claimed.
2. **No pristine holdout.** The old test split has been examined. A final performance claim needs new held-out data.
3. **Small, near-noise-floor gains.** About 0.1 h over EWMA on validation, with no decisive winner among the top three.
4. **Out-of-range extrapolation.** Direct-output models can saturate in unprecedented episodes (observed for B_w at MYPKG). The inference layer warns when the latest dwell is more than 4 training SDs from the port mean, but cannot prevent the error.
5. **Weak at disruption onset and untestable on strikes.** Validation has 9 strike windows from one port. Test-period strikes occurred at ports with no strike history.
6. **Point forecasts only.** No calibrated uncertainty.
7. **Inference expects pre-computed disruption state** (`disruption_active`, `disruption_hours_elapsed`) and a reconstruction flag. Deriving these from live event logs and telemetry quality flags is the caller's responsibility.
8. **Artifact coupling.** Inference requires `DL/Dataset/processed/feature_schema.json` and `scalers.json` exactly as trained (hash-checked).
9. **Repository.** Result CSVs and training logs are excluded by the repository's `*.csv` rule. Checkpoints (`*.pt`) and JSON are not.

## 14. Reproducibility

All commands run from the project root with the project virtualenv. Dependencies: `DL/DL/requirements.txt` (torch 2.5.1 CPU, NumPy 2.0.2, pandas 2.3.3, …), Python 3.9.6.

| Purpose | Command |
|---|---|
| Rebuild the DL dataset (deterministic; **rewrites `DL/Dataset/processed/`**, which must reproduce the hashes in `manifest.json`) | `.venv/bin/python DL/Dataset/data_audit/scripts/run_data_audit.py` then `.venv/bin/python DL/Dataset/scripts/build_dl_dataset.py` |
| Run all DL tests (52) | `.venv/bin/python -m unittest discover -s DL/Evaluation/tests` |
| Training (only when intentionally required; re-running overwrites that phase's checkpoints and logs) | `.venv/bin/python -m dl.training.run_experiments main \| round2 \| ablations \| gru \| transformer` |
| Validation diagnostics (recurrent models) | `.venv/bin/python -m dl.evaluation.evaluate validation` |
| Transformer validation comparison | `.venv/bin/python -m dl.evaluation.compare_transformer` |
| Independent audit (writes only to `DL/Evaluation/evaluation_engineer/`) | `.venv/bin/python -m dl.evaluation_engineer.run_independent_evaluation` |
| Regenerate the model registry (no training) | `.venv/bin/python -m dl.inference.build_registry` |
| Load a model and run a sample prediction | `.venv/bin/python -m dl.inference.demo --model transformer_t_w --port SGSIN --hour 811` |

The one-time test evaluation (`python -m dl.evaluation.evaluate test`) has already been run. It must not be re-run for model selection.
